# نظام إدارة الحصص والمجموعات والاشتراكات الشهرية

تطبيق أندرويد محلي (بدون سيرفر) لإدارة مجموعات التدريس الخصوصي: توليد جدول الحصص تلقائياً من موعد المجموعة الأسبوعي، ضمن **سنة دراسية مقسّمة إلى فصلين (3 أشهر لكل فصل)**، مع متابعة الحضور والاشتراكات والمدفوعات والمديونيات — كل البيانات تُحفظ على جهازك فقط.

---

## الهدف من التطبيق

تسهيل العمل اليومي للمدرّس عبر:

- إدخال بيانات الطالب والمجموعة وموعدها الأسبوعي مرة واحدة.
- توليد مواعيد الحصص (تاريخ + وقت) تلقائياً عبر أشهر الدراسة المحددة مسبقاً.
- تسجيل حضور الحصة للمجموعة كاملة بضغطة واحدة.
- معرفة **إجمالي اللي اتجمع في الشهر** و**مين مدفعش** فوراً بدون حساب يدوي.
- عرض ملخص شهري/فصلي: عدد الحصص، الإيرادات، والمتأخرات.

---

## نموذج العمل المعتمد

| القاعدة | التفاصيل |
|--------|----------|
| التنظيم | الطلاب داخل **مجموعات** |
| السنة الدراسية | مقسّمة إلى **فصلين دراسيين** |
| أشهر الدراسة | تُولَّد تلقائياً من **تاريخ بداية/نهاية كل فصل** (أي مدة، وليست ثابتة على 3 أشهر) |
| موعد المجموعة | أيام أسبوعية ثابتة + فترة زمنية (مثل: السبت والخميس من 5 م إلى 7 م) |
| الجدول | يُولَّد تلقائياً كتسلسل `datetime` عبر أشهر الفصل/السنة |
| عدد الحصص شهرياً | **ناتج عن الجدول** (عدد وقوع أيام المجموعة داخل الشهر الدراسي) وليس رقماً يُكتب يدوياً في كل مرة |
| الدفع | **اشتراك شهري** وليس دفعاً بالحصة المفردة |
| الحضور | يُسجَّل لكل طالب داخل كل حصة مولَّدة |
| المديونية | مقارنة «قيمة الاشتراك الشهري» بـ «ما تم دفعه لهذا الشهر» |

> الحضور مهم للمتابعة التربوية، والحساب المالي يعتمد أساساً على الاشتراك الشهري (ما لم تُفعَّل قواعد التعويض لاحقاً).

---

## السنة الدراسية والفصول والأشهر المحددة مسبقاً

التعليم هنا لا يعتمد على «أي شهر تقويمي»، بل على **سنة دراسية** لها هيكل ثابت:

```text
Academic Year (مثال: 2025/2026)
├── Semester 1  →  3 أشهر دراسية محددة مسبقاً
└── Semester 2  →  3 أشهر دراسية محددة مسبقاً
```

### مثال توضيحي (قابل للضبط في الإعدادات)

| الفصل | الأشهر الدراسية (مثال) |
|------|-------------------------|
| الفصل الأول | أكتوبر، نوفمبر، ديسمبر |
| الفصل الثاني | فبراير، مارس، أبريل |

**ملاحظات مهمة:**

- الأشهر الدراسية **تُعرَّف مسبقاً** عند إنشاء/تفعيل السنة الدراسية.
- الاشتراكات والحضور والتقارير ترتبط بهذه الأشهر فقط (وليس بيناير أو مايو إن لم يكونا ضمن الخطة).
- يمكن إغلاق فصل أو شهر دراسي بعد انتهائه لمنع التعديل العشوائي.

## توليد الجدول الزمني تلقائياً (Auto Schedule)

### الفكرة

عند تعريف المجموعة تحدد فقط **نمط الأسبوع**، والنظام يولّد كل الحصص الفعلية عبر أشهر الدراسة:

**مثال:** المجموعة A تدرس أسبوعياً يومي **السبت** و**الخميس** من **5:00 م** إلى **7:00 م**.

عند تفعيل السنة الدراسية (أو فصل منها)، يقوم النظام بما يلي:

1. قراءة أشهر الدراسة المحددة مسبقاً (6 أشهر = فصلان × 3).
2. داخل كل شهر دراسي، إيجاد كل تواريخ السبت والخميس الواقعة ضمن حدود ذلك الشهر.
3. إنشاء حصة لكل تاريخ بالوقت المحدد (`starts_at` / `ends_at`).
4. ربط كل حصة بالمجموعة + الشهر الدراسي + الفصل + السنة.

### مثال مبسّط لشهر واحد

إذا كان أكتوبر يحتوي على 4 أيام سبت و 5 أيام خميس (حسب التقويم):

| # | اليوم | التاريخ | من | إلى |
|---|------|---------|----|-----|
| 1 | خميس | 2025-10-02 | 17:00 | 19:00 |
| 2 | سبت | 2025-10-04 | 17:00 | 19:00 |
| 3 | خميس | 2025-10-09 | 17:00 | 19:00 |
| … | … | … | … | … |

> عدد الحصص في الشهر = عدد الأيام المطابقة لنمط المجموعة داخل حدود الشهر الدراسي.  
> لذلك مجموعة يومين أسبوعياً غالباً ستحصل على حوالي 8 حصص/شهر، ومجموعة يوم واحد حوالي 4 حصص/شهر — دون إدخال يدوي لكل حصة.

### قواعد التوليد

- التوليد يتم عند: إنشاء مجموعة داخل سنة نشطة، أو تفعيل سنة/فصل، أو إعادة توليد الجدول بعد تعديل الموعد.
- الحصص ذات حضور مسجّل **لا تُحذف تلقائياً** عند إعادة التوليد (يُطلب تأكيد أو تُحدَّث المواعيد غير المستخدمة فقط).
- يمكن إلغاء حصة مفردة يدوياً (إجازة / ظرف طارئ) دون كسر باقي الجدول.
- يمكن تأجيل حصة بتعديل تاريخها/وقتها مع الإبقاء على رقمها وسجلاتها.

## الكيانات الأساسية (Data Model)

### 1. السنة الدراسية (`academic_years`)

| الحقل | الوصف |
|------|--------|
| الاسم | مثل: 2025/2026 |
| تاريخ البداية / النهاية | حدود السنة |
| الحالة | مسودة / نشطة / مغلقة |

### 2. الفصول الدراسية (`semesters`)

| الحقل | الوصف |
|------|--------|
| السنة الدراسية | مرجع |
| الاسم | الفصل الأول / الفصل الثاني |
| الترتيب | 1 أو 2 |
| الحالة | مفتوح / مغلق |

### 3. الأشهر الدراسية (`study_months`)

أشهر محددة مسبقاً داخل كل فصل (عادة 3 لكل فصل):

| الحقل | الوصف |
|------|--------|
| الفصل | مرجع |
| السنة والشهر التقويمي | مثل `2025-10` |
| الاسم المعروض | مثل: أكتوبر 2025 |
| تاريخ البداية / النهاية | حدود الشهر الدراسي (قد تطابق التقويم أو تُضبط يدوياً) |
| الحالة | مفتوح / مغلق |

**لماذا؟** الاشتراك الشهري والحضور والتقارير تُبنى على هذه الأشهر فقط.

### 4. المجموعات (`groups`)

| الحقل | الوصف |
|------|--------|
| الاسم | مثل: مجموعة أولى إعدادي – أ |
| المرحلة / المادة | اختياري للتنظيم والفلترة |
| قيمة الاشتراك الافتراضية | السعر الشهري الافتراضي لطلاب المجموعة |
| الحالة | نشطة / موقوفة |

### 5. نمط الموعد الأسبوعي للمجموعة (`group_schedule_patterns`)

القالب الذي يُولَّد منه الجدول تلقائياً (يمكن أكثر من يوم لنفس المجموعة):

| الحقل | الوصف |
|------|--------|
| المجموعة | مرجع |
| يوم الأسبوع | مثل: السبت، الخميس |
| وقت البداية | مثل: 17:00 |
| وقت النهاية | مثل: 19:00 |

**مثال:** مجموعتان من السجلات لنفس المجموعة A → سبت 17:00–19:00 + خميس 17:00–19:00.

### 6. الطلاب (`students`)

| الحقل | الوصف |
|------|--------|
| الاسم | اسم الطالب |
| هاتف ولي الأمر | رقم التواصل الأساسي |
| ملاحظات | ملاحظات عامة عن الطالب |
| الحالة | نشط / متوقف مؤقتاً / منسحب |

### 7. التحاق الطلاب بالمجموعات (`enrollments`)

| الحقل | الوصف |
|------|--------|
| الطالب | مرجع للطالب |
| المجموعة | مرجع للمجموعة |
| تاريخ البدء | متى انضم للمجموعة |
| تاريخ الانتهاء | اختياري عند النقل أو الانسحاب |
| سعر الاشتراك الخاص | إن وُجد يتجاوز سعر المجموعة الافتراضي |
| الحالة | نشط / منتهٍ |

**لماذا؟** يسمح بنقل الطالب بين المجموعات مع الاحتفاظ بالتاريخ، وبدعم طالب في أكثر من مجموعة إن لزم.

### 8. حصص الجدول المولَّدة (`group_sessions`)

ناتج التوليد التلقائي — كل سجل = حصة فعلية بتاريخ ووقت:

| الحقل | الوصف |
|------|--------|
| المجموعة | مرجع |
| الشهر الدراسي | مرجع لـ `study_months` |
| الفصل / السنة | عبر علاقات الشهر (أو مراجع مباشرة للسرعة) |
| يبدأ في | `starts_at` (تاريخ + وقت) |
| ينتهي في | `ends_at` (تاريخ + وقت) |
| رقم الحصة داخل الشهر | 1، 2، 3… حسب الترتيب الزمني |
| الحالة | مجدولة / مكتملة / ملغاة / مؤجّلة |
| مصدر الإنشاء | تلقائي / يدوي |

### 9. الحضور (`attendances`)

سجل واحد لكل طالب في كل حصة:

| الحقل | الوصف |
|------|--------|
| الحصة | مرجع لـ `group_sessions` |
| الطالب | مرجع للطالب |
| الحالة | حضر / غياب بعذر / غياب بدون عذر / تعويض |
| ملاحظات | مستوى الطالب أو ملاحظة الدرس |

### 10. الاشتراكات الشهرية المتوقعة (`monthly_dues`)

لكل طالب نشط في مجموعة، لكل **شهر دراسي**:

| الحقل | الوصف |
|------|--------|
| الطالب | مرجع |
| المجموعة | مرجع |
| الشهر الدراسي | مرجع |
| المبلغ المستحق | من سعر الطالب أو سعر المجموعة |
| الحالة | مسدَّد / جزئي / متأخر / معفى |

### 11. المدفوعات (`payments`)

| الحقل | الوصف |
|------|--------|
| الطالب | مرجع |
| الشهر الدراسي | الشهر المستهدف بالدفع |
| المجموعة | اختياري إن كان الاشتراك مرتبطاً بمجموعة محددة |
| المبلغ | قيمة الدفعة |
| تاريخ السداد | متى تم الدفع فعلياً |
| وسيلة الدفع | كاش / تحويل / أخرى |
| ملاحظة / رقم إيصال | اختياري |

> يمكن تسجيل أكثر من دفعة لنفس الشهر الدراسي (دفع جزئي ثم إكمال).

## العلاقات بين الكيانات

```text
AcademicYear 1───* Semester 1───* StudyMonth
Group 1───* GroupSchedulePattern
Group + StudyMonths ──(auto generate)──► GroupSession
Group 1───* Enrollment *───1 Student
StudyMonth 1───* GroupSession
GroupSession 1───* Attendance *───1 Student
Student 1───* Payment
StudyMonth 1───* Payment
Student + Group + StudyMonth → MonthlyDue
```

- **سنة ← فصلان ← 3 أشهر لكل فصل:** هيكل دراسي محدد مسبقاً.
- **مجموعة ← نمط أسبوعي:** أيام وساعات التدريس.
- **نمط + أشهر دراسية ← حصص:** توليد تلقائي لمواعيد `datetime`.
- **مجموعة ← طلاب:** عبر جدول الالتحاق.
- **حصة ← حضور:** سجل لكل طالب.
- **طالب ← مدفوعات:** دفعات مرتبطة بالشهر الدراسي.

## الحسابات والتقارير التلقائية

### المطلوب الأساسي شهرياً (أولوية عالية)

هذا هو اللي هتشوفه فوراً في التطبيق لكل **شهر دراسي**:

| المؤشر | إزاي بيتحسب |
|--------|-------------|
| **إجمالي اللي اتجمع في الشهر** | مجموع كل المبالغ المسجّلة في جدول المدفوعات لهذا الشهر الدراسي (لكل الطلاب) |
| **إجمالي المستحق في الشهر** | مجموع اشتراكات الطلاب النشطين في هذا الشهر |
| **المتبقي الإجمالي** | المستحق − اللي اتجمع |
| **مين دفع** | أي طالب مجموع دفعاته لهذا الشهر ≥ اشتراكه |
| **مين دفع جزء** | دفع حاجة، بس لسه عليه باقي |
| **مين مدفعش** | طالب نشط اشتراكه في الشهر > 0 وصافي دفعاته لهذا الشهر = 0 |

> باختصار: التطبيق هيحسبلك **كام اتجمع في الشهر**، ويعرضلك قائمة واضحة بـ **مين مدفعش**.

### لكل طالب (في شهر دراسي محدد)

1. **الاشتراك المستحق** = سعر اشتراك الطالب (أو سعر المجموعة).
2. **إجمالي المدفوع** = مجموع دفعات الطالب لهذا الشهر الدراسي.
3. **المتبقي** = المستحق − المدفوع.
4. **حالة السداد** = مسدَّد / جزئي / متأخر (مدفعش).
5. **ملخص الحضور** = حضور / غياب بعذر / غياب بدون عذر من أصل حصص الشهر المولَّدة (غير الملغاة).

### للملخص العام (Dashboard) — يظهر أول ما تفتح التطبيق

- الشهر الدراسي الحالي + الفصل الحالي.
- **رقم كبير: إجمالي المدفوع هذا الشهر.**
- إجمالي المستحق + المتبقي.
- **قائمة «مين مدفعش»** (الاسم + رقم ولي الأمر + قيمة الاشتراك).
- قائمة «دفع جزئي» إن وجدت.
- عدد الطلاب اللي دفعوا / مدفعوش.
- الحصص القادمة اليوم/هذا الأسبوع.

### شاشة المديونيات (تفصيل أكتر)

فلاتر سريعة:

1. **الكل**
2. **مدفعش** (الأهم)
3. **دفع جزئي**
4. **تم السداد**

مع إمكانية التصفية حسب المجموعة أو الشهر الدراسي.

## الشاشات المقترحة

1. **لوحة التحكم:** إجمالي المدفوع هذا الشهر + قائمة مين مدفعش + الحصص القادمة.
2. **السنة الدراسية والفصول:** تعريف السنة، الفصلين، والأشهر الثلاثة لكل فصل.
3. **المجموعات ومواعيدها:** إنشاء مجموعة + أيام الأسبوع + من/إلى + السعر.
4. **الجدول المولَّد:** عرض/مراجعة الحصص عبر الشهر أو الفصل، مع إلغاء أو تأجيل حصة مفردة.
5. **الطلاب والالتحاق:** إضافة طالب وربطه بمجموعة وسعره.
6. **الحضور:** اختيار مجموعة ← حصة من الجدول ← تحديد حضور الطلاب.
7. **المدفوعات:** تسجيل دفعة وربطها بالطالب والشهر الدراسي.
8. **المديونيات:** مين دفع / مين مدفعش / دفع جزئياً + إجماليات الشهر.
9. **تقارير:** شهرية وفصلية (إيرادات، حضور، متأخرات).

## تحسينات معتمدة في هذا التصور

### 1. الجدول يُولَّد من النمط الأسبوعي لا يُدخل يدوياً
المدرّس يعرّف «السبت والخميس 5–7»، والنظام يملأ كل التواريخ عبر أشهر الدراسة.

### 2. السنة الدراسية هي الإطار الزمني الحقيقي
فصلان × 3 أشهر محددة مسبقاً = 6 أشهر دراسية فقط للاشتراك والحضور والتقارير.

### 3. عدد الحصص نتيجة وليس فرضاً ثابتاً
بدل تثبيت «4 حصص» دائماً: العدد = وقوع أيام المجموعة داخل الشهر الدراسي.  
(مجموعة يوم واحد/أسبوع ≈ 4، ومجموعة يومين/أسبوع ≈ 8 — حسب التقويم.)

### 4. جدول التحاق (`enrollments`) بدل ربط مباشر فقط
للحفاظ على تاريخ النقل بين المجموعات.

### 5. سعر المجموعة افتراضي + سعر خاص للطالب عند الحاجة

### 6. فصل الحضور عن المال
الدفع على الاشتراك الشهري، والحضور للمتابعة التربوية.

### 7. دعم الدفع الجزئي
مستحق + مدفوع + متبقي.

### 8. حالات حضور جاهزة للتعويض لاحقاً
`حضر` | `غياب بعذر` | `غياب بدون عذر` | `تعويض`

### 9. حماية إعادة التوليد
لا تُمسح الحصص التي سُجّل عليها حضور دون تأكيد صريح.

### 10. سجل تدقيق بسيط
مفيد عند وجود أكثر من مستخدم لاحقاً.

## نظام التعويض (اختياري — مرحلة لاحقة)

| السيناريو | السلوك المقترح |
|----------|----------------|
| غياب بعذر | الاشتراك ثابت؛ يُسمح بحصة تعويض |
| غياب بدون عذر | لا تعويض تلقائي (أو حسب السياسة) |
| حصة تعويض | جلسة إضافية يدوية أو ربط `makeup_for_attendance_id` |

**توصية الإصدار الأول:** تسجيل أنواع الغياب فقط، وإدارة التعويض يدوياً بملاحظة أو حصة يدوية، ثم أتمتته لاحقاً إن لزم.

## ما هو خارج النطاق حالياً (يمكن إضافته لاحقاً)

- رسائل واتساب/SMS تلقائية لأولياء الأمور.
- تطبيق للطالب أو ولي الأمر.
- جداول امتحانات ودرجات مفصّلة.
- محاسبة ضريبية متقدمة.
- تعدد المدرّسين والصلاحيات المعقّدة (يمكن البدء بمستخدم أدمن واحد).
- استثناءات العطل الرسمية المتقدمة (يمكن البدء بإلغاء يدوي للحصة).

## مبادئ التصميم التشغيلي

1. **عرّف السنة مرة واحدة:** فصلان + 3 أشهر لكل فصل.
2. **عرّف المجموعة وموعدها الأسبوعي مرة واحدة.**
3. **دع النظام يولّد الجدول** عبر الأشهر الدراسية.
4. **سجّل الحضور من الحصص المولَّدة.**
5. **ادفع شهرياً** على الشهر الدراسي، ودع النظام يحسب المديونية.
6. **ابدأ بسيطاً:** سنة دراسية → مجموعات → جدول تلقائي → حضور → مدفوعات → مديونية.

## التقنيات المعتمدة (v1)

| الطبقة | التقنية |
|--------|---------|
| التطبيق | **Expo SDK 57 + React Native + Expo Router** (مجلد `mobile/`) |
| التخزين | **expo-sqlite** محلياً على الجهاز (بدون سيرفر) |
| اللغة | عربية فقط + RTL |
| النسخ الاحتياطي | تصدير/استيراد JSON عبر مشاركة الملف |

### تشغيل التطبيق

```bash
cd mobile
npm install
npx expo start
```

ثم افتح على Expo Go أو محاكي Android.

### كيف يعمل بدون سيرفر؟

- كل البيانات في SQLite على الجهاز.
- لا إنترنت مطلوب للاستخدام اليومي.
- النسخ الاحتياطي عبر تصدير ملف JSON (احفظه يدوياً على Google Drive عند الحاجة).

### قيود

- البيانات على جهاز واحد؛ غيّر الهاتف فقط بعد الاستيراد من نسخة احتياطية.
- لا مزامنة تلقائية بين هاتفين في v1.
